# 开发模式：人机协作闭环

```
你（决策/验证） ⇄ AI agent（执行/迭代） ⇄ 外挂平台（编译/发布/存储）
```

## 一句话

RikkaMinis 不是用传统 IDE 写的，而是用 **RikkaMinis 本身** 写的——每次修改、构建、测试、迭代都在这个端侧智能体的协助下完成。

## 角色

| 角色 | 做什么 |
|---|---|
| **你（决策者）** | 提出需求、拍板方案、真机验证、决定收敛或重做 |
| **AI agent（执行者）** | 分析问题、执行 shell、写代码、调试、循环迭代直到你确认 |
| **外挂平台（基础设施）** | GitHub CI（编译/发布）、Cloudflare Worker（CI 状态桥）、HuggingFace Dataset（跨设备语义记忆持久化） |

## 工作流

```
你提需求 → agent 分析/执行/写代码 → 推送到 GitHub → CI 编译 → 你装 APK 验证 → 反馈 → 循环
```

这是一个典型的 **dogfooding（自用开发）** 闭环：我们直接用这个 app 来开发这个 app 本身。你装 APK 使用，agent 写代码修改，推上去编译，你装回来继续验证，直到功能收敛。

## 三平台手

在这个闭环中，三个外挂平台充当 agent 的"手"：

- **GitHub** — 代码仓库 + CI 构建（自动编译 APK 并发布到 `android-latest`）
- **Cloudflare** — Workers 边缘计算（一个私有 Worker 提供 CI 状态查询端点，零 token 开销）
- **HuggingFace** — 语义记忆数据持久化（跨设备、不依赖本地文件）

三者共同构成了 agent 的操作边界：**一端脑（设备）、三平台手（GitHub + CF + HF）**。

## 这种模式的意义

1. **验证了端侧智能体足以支撑真实开发**——所有工具链都跑在手机上，没有依赖远程桌面或 IDE
2. **人机协作的效率远高于纯手工或纯 AI**——你掌控方向，agent 执行细节，循环收敛
3. **可复现**——任何能运行这个 app 的人都能复现这个开发模式，不需要特殊环境
